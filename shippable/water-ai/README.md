# @teamwater/water-ai

The phone side of Water AI: no dependencies, TypeScript, and byte-compatible with Water Connect. See [`../README.md`](../README.md) for what it's for and how it fits into the app.

## `WaterAI` (high level)

```ts
new WaterAI(credentials, { crypto?, fetch?, now? })
```

| Method | Online? | What it does |
|---|---|---|
| `WaterAI.connect(connectUrl, setupToken)` | yes | Trades the one-time setup token for `DeviceCredentials`: `deviceId`, `groupId`, a 32-byte `deviceKey`, `models` and `defaultModel`. The token works once and expires after 5 minutes. |
| `ai.ask(question, modelIndex?)` | **no** | Returns `{ requestId, frame }`. Send `frame` over the mesh as an `ai_request` transfer. Questions are capped at 400 UTF-8 bytes, and `modelIndex` is 0–255, an index into `models`. |
| `ai.receive(answerFrame)` | **no** | Opens an `ai_response` frame. Returns `{ requestId, outcome, text, sources, duplicate }` for this phone's own questions, or `null` if the frame belongs to someone else. |
| `ai.questions()` | no | The questions this phone has asked, with their status. To retry, resend the same `frame`; the request ID means no second AI call. |
| `ai.relay(requestFrame)` | yes | Gateway role. Forwards another phone's sealed request to Water Connect and returns `{ state: 'answered', frame }` to send back, or `{ state: 'already_claimed', retryAfterSeconds }` when another gateway is already answering it. |
| `ai.receipt(requestId)` | yes | Gateway role. Tells Water Connect the asker received the answer. |

`outcome` is one of:

| Outcome | Meaning |
|---|---|
| `ok` | Grounded in the field guide. `sources` lists the facts it used. |
| `general` | Not in the field guide, so the model answered from its own knowledge. Show it as possibly wrong. |
| `no_grounding` | "I don't know". Strict mode is on and no model was asked. |
| `blocked` | Looked like a prompt injection. No model was asked. |
| `over_budget` | The group used its daily AI budget. |
| `error` | Something failed. `text` says what. |

## Low-level protocol functions

These are for a custom transport or for testing: `buildRequestFrame`, `parseRequestFrame`, `openAnswerFrame`, `answerFrameRequestId`, `signRelayBody`, `seal`, `unseal`, `newRequestId`, `OUTCOME_CODES`, `MAX_QUESTION_BYTES`, `FRAME_OVERHEAD_BYTES`.

## Wire format

```
sealed        = nonce(12) | AES-256-GCM ciphertext | tag(16)
                AAD = requestId(16) | deviceId(u32 big-endian) | 'Q' or 'A'
request frame = requestId(16) | askerDeviceId(u32 BE) | sealed( modelIndex(1) | question UTF-8 )
answer frame  = requestId(16) | sealed( outcome(1) | answer UTF-8 [ | 0x1E | source ids, comma-separated ] )
relay call    = POST {connectUrl}/v1/relay  {"request_id","device_id","sealed": base64}
                headers X-Device-Id, X-Timestamp (unix seconds), X-Signature = hex HMAC-SHA256(deviceKey, "<ts>.<body>")
```

`test-vectors.json` holds known-good bytes generated by the server. Regenerate it with `python -m connect.vectors` if the format ever changes on purpose.
