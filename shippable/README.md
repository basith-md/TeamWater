# Shippable

Code in this folder is meant to run on real phones, not just in the demo. Everything else in the repo (the console, the mesh simulator, the Python services) exists to demo or serve it.

| Folder | What it is | Runs on |
|---|---|---|
| [`water-ai/`](water-ai/) | The phone side of Water AI: setup, sealing questions, opening answers, and acting as an internet gateway for other phones | iPhone / Android (React Native, Expo), or any JavaScript runtime with Web Crypto |

The server side it talks to is [`connect/`](../connect/) (Water Connect). Deploy it separately; see [Server side](#server-side) below.

## What problem it solves

A Water phone has no internet, but someone nearby might. Water AI lets an offline phone ask a question that hops over the LoRa mesh to any group phone with internet (the *gateway*), which forwards it to Water Connect and carries the answer back.

```
 Asker phone (offline)                Gateway phone (has internet)            Water Connect
 ─────────────────────                ────────────────────────────            ─────────────
 ai.ask(question)
   → request frame ── LoRa mesh ──▶   ai.relay(frame) ── HTTPS, signed ──▶   checks, grounds, asks the model
                                      ◀── sealed answer ─────────────────    stores the answer
   ◀── answer frame ── LoRa mesh ──   reply.frame
 ai.receive(frame)
   → "1.7 seconds."  [field_guide-01]
                                      ai.receipt(id) ───────────────────▶    marks it delivered
```

The module only makes and reads **bytes**. Moving bytes over the radio is the mesh layer's job (CHRP's LoRa stack on hardware, `backend/` in our simulator).

## Guarantees

- **The gateway cannot read or change the question or the answer.** Each phone gets its own 256-bit key at setup. Requests and answers are sealed with AES-256-GCM, bound to the request ID, the asker's device ID and the direction. Any altered byte is rejected.
- **No API keys on phones or on the radio.** Model and PRISM keys stay on Water Connect.
- **One AI call per question.** The request ID is the idempotency key. If an answer is lost or a different gateway retries, Water Connect returns the stored answer instead of calling the model again, and `receive()` flags duplicates.
- **Honest answers.** The answer says where it came from: `ok` means grounded in the field guide, with source IDs. `general` means the model's own knowledge, which may be wrong. Other outcomes are `no_grounding`, `blocked`, `over_budget` and `error`.
- **Byte-compatible with the server, enforced by tests.** `water-ai/test-vectors.json` is generated by the Python server (`python -m connect.vectors`). The TypeScript tests reproduce every byte of it, and a Python test fails if the server's format drifts from the file.

## Using it in the Water app

```ts
import { WaterAI } from '@teamwater/water-ai';

// 1. Setup, once, while online. Water Connect redirects back to water://connected?token=…
const credentials = await WaterAI.connect('https://connect.example.com/connect', token);
await secureStore.save('water-ai', credentials);   // the device key belongs in Keychain / Keystore

const ai = new WaterAI(credentials);

// 2. Ask, fully offline. Hand the frame to the mesh as an `ai_request` transfer to a gateway.
const { requestId, frame } = await ai.ask('How fast is Long Fast?', modelIndex);
mesh.send(gatewayNode, frame, { kind: 'ai_request' });

// 3. When an `ai_response` transfer arrives:
const answer = await ai.receive(bytes);   // null if it isn't this phone's question
if (answer && !answer.duplicate) show(answer.text, answer.outcome, answer.sources);

// 4. Gateway role: only on a phone that currently has internet.
const reply = await ai.relay(requestFrameFromMesh);
if (reply.state === 'answered') mesh.send(askerNode, reply.frame, { kind: 'ai_response' });
// When the mesh confirms the asker received it:
await ai.receipt(reply.requestId);
```

The full API is in [`water-ai/README.md`](water-ai/README.md).

## Radio budget

A request frame is the question plus **49 bytes**: 16-byte request ID, 4-byte device ID, 1-byte model choice, 12-byte nonce and 16-byte tag. Questions are capped at 400 bytes. An answer frame is the answer (about 300 bytes at most) plus source IDs plus 45 bytes (request ID, outcome byte, nonce, tag). The mesh layer splits frames into 230-byte LoRa packets and reassembles them. At Long Fast, a typical question and answer is 2 packets each way.

## Requirements on the phone

- **Web Crypto** (`crypto.subtle` with AES-GCM and HMAC-SHA256, plus `crypto.getRandomValues`). Browsers and Expo web have it. On React Native, install a WebCrypto implementation such as `react-native-quick-crypto` and pass it as `new WaterAI(creds, { crypto })` if it isn't global.
- **`TextEncoder` / `TextDecoder`.** Recent Hermes versions provide both. On older runtimes, add a polyfill.
- **`fetch`**, only for setup and the gateway role.
- **Secure storage** for the credentials (`expo-secure-store`, Keychain, Keystore). Never log `deviceKey`.

## Server side

Water Connect lives in [`connect/`](../connect/). It runs standalone with `uvicorn connect.app:create_app --factory`, or mounted in the mesh service at `/connect`. It needs `connect/.env`, created from `connect/.env.example`.

## Before real phones: production checklist

What's done and tested:
- The protocol and the module.
- The server flow.
- Gateway handover without a second AI call.
- The simulator end to end.
- A live run of this module against the real server and model (`tests/integration/water-ai-live.test.ts`).

Still needed before it ships on hardware:

- [ ] Test on physical iPhones and Android phones, including the Web Crypto polyfill and secure storage.
- [ ] Wire `ai_request` and `ai_response` frames into CHRP's real LoRa transport.
- [ ] Deploy Water Connect over HTTPS with its own domain. Set `WATER_DEMO=0`, so there's no shared account, and keep `WATER_MASTER_KEY` in a secret manager.
- [ ] Let users choose `REQUIRE_GROUNDING`, or set a policy. `0` lets the model answer uncovered questions, labelled as general knowledge.
- [ ] Add rate limits and abuse controls on `/v1/relay`. Today there's a per-group daily budget.
- [ ] Add device key rotation and revocation from the group page. Today, deleting the device row revokes it.
- [ ] Persist unanswered questions on the phone, so a restart doesn't lose them. Today `WaterAI` keeps them in memory.
- [ ] Tell users that questions are sent to a third-party model provider. The sign-up page says this.
