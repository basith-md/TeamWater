# TeamWater frontend implementation plan

> For agentic workers: use test-driven development and the parallel-agent workflow requested by the user. Work only within assigned directories; parent owns integration. Do not spawn additional agents or commit another worker's files.

**Goal:** Working Expo messenger and interactive browser console for the two-person mesh demo.
**Architecture:** Shared native phone UI, shared typed client, separate Expo and Vite entries. Live backend adapter plus explicitly labeled authored replay fixtures.
**Tech Stack:** Expo 57, React 19.2, React Native 0.86, React Native Web, Vite, TypeScript, Vitest, Playwright.
**Spec:** `docs/superpowers/specs/2026-10-10-frontend-design.md`

## Global constraints

Do not change backend/ or service/. The backend-owned shared/typescript/api.ts generated from openapi.yaml is the authoritative wire contract; packages/core/src/types.ts defines only normalized UI state. Both phones share the same MeshClient in the browser. Offline is not Delivered. No inferred network metrics when backend lacks telemetry. All fixture data is labeled demo replay. Use tests first and record observed red/green commands in docs/implementation/<task>.md. Work on feat/expo-mesh-console in the existing clean checkout; file ownership isolates agents.

## Review focus

1. Missing/corrupt server snapshots must not crash or invent delivery.
2. A stale WebSocket after switching endpoint/mode must not contaminate the next session.
3. Failed send must preserve draft and show a recoverable error.
4. ACK-only state must not claim end-to-end verified delivery.
5. A relay outage replay must display a continuous valid route or truthful failure.
